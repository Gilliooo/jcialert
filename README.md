# JCIAlert

Windows tray app that watches Indonesian financial news feeds and pops up when
a headline names a ticker you care about. Python standard library only, plus
`pystray` and `pillow` for the tray icon; tkinter for the windows.

Sibling to IDXAlert. Same tray / popup / options interface, different feed:
**corporate news about listed companies**, instead of IDX disclosures.

Alerts fire when a watchlist ticker or its company name appears in a
**headline**. Index-level news (IHSG, rupiah, BI rate, foreign flows) is
deliberately not an alert — it is rarely actionable inside the window where
interrupting you is worth it.

The two apps are built to run side by side: separate config, separate
`seen.json`, separate Run key, separate mutex, and a different tray icon
(stacked lines here, bars in IDXAlert). Sharing any of that is what caused the
403/503 run on 2026-09-01.

---

## Building it from a clone

```
git clone <this repo>
cd jcialert
python -m pip install pystray pillow pyinstaller

run_tests.bat             the 15 suites, offline, ~10 seconds
build.bat                 suites, then dist\JCIAlert.exe
make_portable.bat         assembles installer\JCIAlert-<version>-portable.zip
make_installer.bat        all of the above, then the Inno Setup .exe
```

Python 3.10+ on Windows. `run_tests.bat` needs nothing but Python — no
network, no display, no IDX. Building the exe needs the three packages above.

**Two things the repo does not carry, and what happens without them:**

| not in the repo | consequence | how to get it |
|---|---|---|
| `fixtures/` | the parsers and the end-to-end chain are not tested; the suites say so in a banner rather than passing quietly | `python probe_sources.py --save-fixtures fixtures` — needs to run from Indonesia, on a weekday, during market hours |
| `dist/`, the portable zip, `installer/Output/` | nothing to install yet | `make_installer.bat` |

`emiten.json` **is** in the repo — 250 KB of IDX ticker symbols and company
names, generated by `build_aliases.py`. The app refuses to start without it, so
shipping it is what makes a clone runnable. It goes stale as companies list and
delist; refresh with `python build_aliases.py --report`.

`config.json` is in the repo too, with the tuned categories, the
`global_exclude` roundup markers and the source list measured over a full
trading day. Its watchlist is empty, which means **every ticker**, not none.

## Installing it

```
make_installer.bat        suites -> JCIAlert.exe -> portable zip -> installer\Output\JCIAlert-Setup-<version>.exe
```

Needs [Inno Setup 6](https://jrsoftware.org/isdl.php) (free). The setup is
**per-user**: it installs to `%LOCALAPPDATA%\Programs\JCIAlert`, needs no
admin and raises no UAC prompt. That is not a shortcut — `config.json` lives
beside the exe, so a Program Files install would run fine and then fail to save
a single setting. The wizard refuses a folder your account cannot write to.

An upgrade replaces only `JCIAlert.exe` and `emiten.json`. Your `config.json`,
`seen.json`, `news.csv` and `logs\` are never touched. The
uninstaller asks before deleting them, and removes the autostart entry — which
the app itself writes and would otherwise leave pointing at a deleted exe.

**No Inno Setup, or a machine that blocks unsigned installers:**

Unzip `installer\JCIAlert-<version>-portable.zip` anywhere and:

```
SETUP.bat      copies into your profile, makes a Start Menu shortcut, starts it
REMOVE.bat     removes it   (/purge to delete settings and history too)
```

Neither installer is code-signed, so SmartScreen will warn the first time
("More info" → "Run anyway"). Signing needs a certificate; nothing in the build
can work around it.

## Running it from source

```
python jci.py --watch     the polling loop, in this console
python jci.py --once      poll once, show every decision, write nothing
dist\JCIAlert.exe         the tray app, after build.bat
```

`build.bat` refuses to build if any suite fails, if `emiten.json` is missing,
or if JCIAlert.exe is already running — Windows locks a running exe, and
PyInstaller does not find that out until the last step of a two-minute build.
It copies `emiten.json`, `config.json` and `aliases_manual.json` into `dist\`
only if they are not already there, so your live config is never overwritten
by a rebuild.

First run is quiet by design: each source's current backlog is recorded and not
alerted, so you do not get a hundred hours-old headlines at startup. The log
says so, naming the sources and counts.

## The two windows

**News dashboard** — the first tray item and the double-click default.

- Every headline the app has seen, not just the ones that alerted. The filters
  are a **view**: `Show everything` widens the table to the rejected ones, and
  the `Why / rule` column says which rule accepted it or which gate turned it
  away. That is the only way to tell a rule that is too tight.
- Search, ticker, source, and a When filter: Today / This week / This month /
  This year / All. Calendar boundaries in WIB, not rolling windows.
- Click a column heading to sort; click again to reverse. Blanks sink to the
  bottom either way.
- Unopened stories are tinted. Double-click or Enter opens one; the receipt is
  saved immediately.
- **Status** tab: per-source health, five states — `ok`, `STALE`, `FAILING`,
  `BACKED OFF` (with the wait remaining), `not tried`. Only sources you have
  switched on appear, and only those colour the tray icon.
- **Actions** tab: every tray menu item as a button.

**Options** — speed, grouping, alerts, notifications, watchlist, sources,
filters. Refuses to save a config that could never alert.

## Settings worth knowing

| setting | what it does |
|---|---|
| `watchlist` | tickers to alert on. **Empty means EVERY ticker, not none.** |
| `corner` | which corner the popup appears in: `bottom right` (default), `bottom left`, `top right`, `top left` |
| `max_visible` | rows shown before the popup scrolls |
| `duration_seconds` | `0` = only the X closes it |
| `max_item_age_minutes` | nothing older than this ever alerts, whatever the seen-set says. This is what makes a restart safe |
| `seed_on_first_run` | swallow a source's backlog the first time it answers |
| `sources` | per source: `enabled`, and optionally `url` to point one at a different feed path without rebuilding |

## When it does not start

A tray app built `--noconsole` has no stderr, so a failed start used to produce
**nothing at all** — no window, no icon, no log. It now checks every reason it
can fail before building anything and puts the answer in a dialog, plus
`%LOCALAPPDATA%\JCIAlert\startup-error.txt`.

If there is no icon, in this order:

1. **Look under the `^` chevron in the tray.** Windows 11 hides new tray icons
   there by default. This is the commonest cause and costs nothing to check.
2. **Right-click the tray icon → Diagnostics...**, or run
   `JCIAlert.exe --doctor` — it reports missing files, an unwritable folder, a
   broken config, or a second copy already running.
3. **Check the app is beside its files.** `emiten.json` is 250 KB of ticker
   data and is deliberately *not* bundled into the exe, so it can be refreshed
   without a rebuild. Copy `JCIAlert.exe` somewhere on its own and it cannot
   start. Copy the whole folder, or use the installer.

## Commands

```
jci.py --once [--commit]   poll once, show every decision, write nothing
jci.py --doctor            check every reason the app can fail to start
jci.py --watch             run the loop in this console
jci.py --replay            re-run today's rules over every recorded headline
jci.py --report            summarise a day of alerts from news.csv
jci.py --density           which sources actually carry emiten news, measured
jci.py --verify-sources    check each source's newest item is not stale
jci.py --show-config       where things live, expanded rules, validation
```

**`--replay` is how you check a watchlist before committing to it:**

```
jci.py --replay --watchlist BBCA,BMRI,BBRI
```

It re-runs the current rules over every headline in `news.csv` — including the
ones that were rejected — and reports what would have alerted. If anything gets
through that is not on the list, it says `*** LEAK ***` and exits non-zero. It
does not apply the age cutoff or story clustering, because both depend on when
a poll happened; the counts therefore run higher than the day produced, and it
says so.

## What it writes

| file | what it answers |
|---|---|
| `news.csv` | every headline it *saw*, with why each did or did not alert. Rotates at 64 MB |
| `opened.json` | which stories you have clicked |
| `seen.json` | item ids, live story clusters, which sources are seeded |
| `logs\jci-YYYY-MM-DD.log` | state changes and an hourly heartbeat — never a line per check |

## Sources

Bot protection lives on article HTML pages, not on feeds. This is an RSS
aggregator plus a few plain-HTML scrapes — never a headless browser.

```
python probe_sources.py --only bisnis,kompas --save-fixtures probe\
```

`--only` takes a kind (`rss` / `html` / `unknown`) or comma-separated name
fragments. `--save-fixtures` writes the raw bytes so a parser can be written
and tested offline against real markup. **Run it from your own machine** — a
datacenter IP is refused by several of these sites, and both the Claude
container and the desktop sandbox have no route to them at all.

Measured on 2026-09-05 from a residential connection: 17 work, 2 return a
valid-but-dead 200 (Okezone last published in 2016, Tempo 12 days stale), 8
refuse. Every source adapter therefore carries a freshness guard — a clean 200
over dead content has no other symptom.

**`kompas-money` is registered but OFF.** Kompas has no RSS any more — the
classic paths 404 and `rss.kompas.com` is a partner API that 403s every
endpoint — so it is scraped from the HTML index at `money.kompas.com`. The
publication time comes out of the article URL (`/read/2026/09/14/113756426/` is
11:37:56 WIB), because the page itself only says "20 jam lalu" and a relative
stamp cannot drive an age cutoff. Tick it on if its density earns the noise;
it is polled every third tick because the index is 198 KB.

**Bisnis.com is blocked and is not registered.** Eight paths, all 403, from a
residential IP, with the full Chrome header set and a same-site `Referer`
retry. There is no header left to try, and an entry that can never be ticked on
is clutter in the Options list rather than an option.

IQPlus was removed in 1.0 — unreachable since 2026-09-08, 45 seconds of
timeout per attempt while dead. Its parser went too, in 1.0.1: it was the only
ALL-CAPS source and the only one carrying tickers in its URL slug, and keeping
a dead parser alive kept four other mechanisms alive with it (rule 4 below, the
ambiguous-word penalty, the slug-upgrade step and the macro-code filter). Bring
it back by restoring one file from git, not by maintaining it against a wire
nobody can reach.

## The three matching rules

Indonesian tickers are exactly four letters, and every rule leans on that.

1. **Parenthetical** — `Bank Mandiri (BMRI) Tebar Dividen`. Near-zero false
   positives; Indonesian financial media parenthesises the ticker on first
   mention. Confidence 1.00.
2. **Alias** — `Bos Bank Mandiri Jelaskan ...` → BMRI. Recall depends entirely
   on how well `emiten.json` is maintained. 0.90–0.95.
3. **Bare token** — the capitals are themselves the signal. 0.60.

There was a fourth, for ALL-CAPS wires where capitalisation says nothing: a
ticker in the first word or two scored 0.85, later 0.45, both docked 0.30 when
the code was also an ordinary Indonesian word (BUKA, CUAN, EMAS...). It went
with IQPlus. Every registered source writes mixed case, where the capitals
already disambiguate and that penalty would have cost real coverage of exactly
the names that make headlines.

## Filters

A filter is a **list of rules, OR'd together**. One global AND across ticker,
category and keyword breaks immediately, because you do not want the same
sensitivity for every name:

    "anything at all about BBRI"                     a name you own
    "only buybacks and M&A across your sector"       names you watch
    "any suspension, any ticker"                     a thing you never miss

Within one rule, every field you fill in must pass:

| field | meaning | empty means |
|---|---|---|
| `tickers` | hit must be one of these | any ticker |
| `categories` | headline must match one | any category |
| `categories_exclude` | headline must match none of these | nothing excluded |
| `require` | EVERY term must appear | no requirement |
| `any_of` | AT LEAST ONE must appear | no requirement |
| `exclude` | NO term may appear | nothing excluded |
| `sources` | item must come from one | any source |
| `max_tickers` | drop headlines naming more than this | no limit |
| `min_confidence` | floor on the ticker match | 0.0 |

**An empty list means ANY, never NONE.** `"tickers": []` matches every ticker,
and so does an empty watchlist.

`global_exclude` beats every rule. `require_ticker: false` makes a keyword-only
rule for index or macro news with no company in it.

When a headline is refused, the reason names the gate that closed and the rule
that closed it — `My coverage: ticker match too weak (0.45, needs 0.50)`,
`My coverage: names 5 tickers, more than the 2 this rule allows`. With several
rules, the one reported is the rule the headline came *closest* to satisfying,
because that is the one worth editing.

### Term syntax

Terms match on token boundaries, never raw substrings — `laba` will not fire on
`kelabakan`. Indonesian affixes need wildcards:

```
dividen         exact token
akuisisi*       prefix     akuisisinya
*akuisisi       suffix     mengakuisisi
*akuisisi*      anywhere   diakuisisinya
tebar dividen   a phrase, consecutive words
borong * saham  up to three words between
```

Categories are named keyword bundles so the common case is two clicks rather
than twenty keywords. Edit them freely; they are not a fixed taxonomy.

### The false positive worth knowing about

`10 Saham yang Rugi Sepekan, RGAS Pimpin Top Losers` matches the `earnings`
category — `rugi` there is a price move, not an accounting loss. Categories
cannot tell the difference, so that is what `exclude`, the roundup markers and
`max_tickers` are for. Both halves are pinned by tests: the rule fires without
the guard, and a real earnings headline still gets through with it.

## Clustering

One story reaches you once. Later outlets attach to the same popup row, and a
later story about a ticker already on screen joins that ticker's menu rather
than opening a second row.

Similarity is the **overlap coefficient** over content tokens, after the
company's own name is stripped — clusters are compared within a single ticker,
so the name is constant noise that would make every story about a company look
alike. Overlap rather than Jaccard because headline lengths differ wildly
between outlets, and a wire one-liner is largely *contained* in a long CNBC
headline without sharing much of its union.

Clusters are persisted, so a restart does not re-alert every story the other
outlets are still carrying.

**Known limit:** this works within one language. An English headline and an
Indonesian one about the same event share almost no tokens and would both
alert. A ticker-and-time rule used to cover that; it went in 1.0.1 along with
the only English source ever measured (IDN Financials, which refuses us). Every
registered source is Indonesian, so the case does not arise.

## Tests

```
run_tests.bat
```

15 suites, all offline, all run by `build.bat` before it will build. There is
one list of them, in `run_tests.bat`; `build.bat` calls it rather than keeping
a second copy.

The governing rule is that **a skipped test looks identical to a passing one**,
so the suites go out of their way not to skip:

- The window and tray suites stub fake toolkits into `sys.modules` and drive
  the real code path, instead of skipping because there is no display.
- `test_aliases.py` also walks every module's AST for undefined names,
  duplicate definitions and invalid escape sequences — the network paths
  cannot be exercised where this code is edited, so they are checked
  statically.
- `test_jci.py` checks the *build* as well as the code: that `build.bat`
  looks for a running exe before it does anything expensive, that it runs the
  suites before PyInstaller, and that no suite asserts on a build artefact
  that does not exist yet.

Where a suite genuinely cannot run — `fixtures/` is not in this repo — it
prints a banner you cannot miss and names the command that fixes it. It still
exits 0, because a clone has to be able to build.

## Contributing

Open an issue before a large change; this is a personal tool and its
constraints are unusual (stdlib-only engine, no network where it is edited,
a `--noconsole` exe with no stderr). If you do send a patch:

- `run_tests.bat` must be green, and new behaviour needs a check in the
  matching suite.
- No new runtime dependency for something a few lines of stdlib can do.
- Comments explain *why*, especially where the obvious implementation is
  wrong — most of the comments in this codebase are a bug's headstone.
